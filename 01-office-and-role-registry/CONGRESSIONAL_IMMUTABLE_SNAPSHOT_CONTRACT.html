Congressional Immutable Snapshot Contract

  1. Resolve and validate the requested endpoint and allowed final host.
  2. Record request URI, method, nonsecret request headers, response status, final URI, response headers, retrieval start, and retrieval finish.
  3. Acquire raw bytes once for the receipt event.
  4. Compute SHA-256 over exact bytes before decoding, parsing, normalization, or formatting.
  5. Store only repository-permitted HTML representations; non-HTML source bytes require a separately approved storage boundary and may not be silently converted into canonical HTML.
  6. Bind snapshot ID, endpoint ID, parser prohibition state, content type, encoding claim, byte count, hash, and transaction time.
  7. Never overwrite an earlier snapshot. Identical bytes create a no-change receipt; different bytes create a new snapshot candidate.
  8. Parsing reads an immutable snapshot and emits derived records carrying snapshot hash, parser ID, parser version, and source locations.
  9. Secrets, API keys, cookies, and authorization headers are never stored in repository artifacts.

Effect: OBSERVATION_ONLY.
