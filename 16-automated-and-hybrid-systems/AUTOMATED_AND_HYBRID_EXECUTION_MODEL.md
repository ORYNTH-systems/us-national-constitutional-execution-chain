# Automated and Hybrid Execution Model

This domain records the use of software, statistical, machine-learning, or mixed human-system capability in a public execution path. Capability, output, access, or operational speed does not create governmental authority.

## Required authority boundary

Every consequential automated or hybrid action links to a current accountable principal, a source-bound authority path, an approved purpose, a defined jurisdiction and scope, current delegation state, evidence and consequence gate, and an execution receipt. A system may observe, classify, recommend, draft, calculate, route, or perform a bounded ministerial action only within the recorded conditions.

## High-impact boundary

Before a system-supported action can produce a high-impact effect, the record must identify the effect type, affected subject or class, accountable principal, authority and delegation, review requirement, evidence basis, contest or remedy route, and stop or revocation condition. Where a required condition is unresolved, the system result remains an observation or recommendation and cannot become an effect through this domain.

## Integrity conditions

- Agent, model, tool, vendor, or operator identity is not an authority source.
- Delegation may narrow a principal's authority; it cannot enlarge it or transfer it without a valid source-linked path.
- Access must be scoped, time-aware, and revocable; stale authorization blocks action.
- A system output is not evidence, a decision, or a legal conclusion unless separately admitted by the appropriate record and gate.
- A human review label does not cure a missing authority, predicate, scope, or receipt.

This model does not regulate AI or decide what any institution may lawfully automate. It provides an inspectable execution boundary for any covered system once an authorized institution applies it.
