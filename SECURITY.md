# Security and responsible disclosure

## Scope

This repository is a public reference framework and does not operate a live governmental service. Nevertheless, integrity defects, malicious artifacts, exposed secrets, unsafe links, provenance failures, or release-reconstruction defects should be treated seriously.

## Reporting

Use GitHub private vulnerability reporting when that option is available on this repository. If it is unavailable, do not post exploit details, credentials, personally identifying information, or unredacted sensitive materials in a public issue. Open a minimal public issue requesting a private reporting path, without sensitive details.

## What to include

- A concise description of the affected repository path or release.
- Reproduction steps or an integrity comparison that can be independently checked.
- Expected and observed behavior.
- Any known impact on provenance, release reconstruction, or fail-closed boundaries.

## What not to claim

A repository defect is not, by itself, a governmental defect or a determination about any public institution. Reports must keep that distinction intact.
