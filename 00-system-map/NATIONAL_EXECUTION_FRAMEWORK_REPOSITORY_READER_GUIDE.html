Repository reader guide

Reading sequence

  1. Read README.md, PUBLIC_START_HERE.md, and the system-map materials for scope.
  2. Read the relevant domain directory for its constitutional, institutional, and source boundaries.
  3. Inspect source catalogues and snapshot receipts before relying on a proposal.
  4. Follow proposals through normalization, conflict routing, semantic enrichment, evidence packets, and blank decision ledgers.
  5. Read adversarial test results and conformance records to see what the framework refuses to permit.
  6. Read freeze, manifest, digest, and release records to reproduce the release state.

Repository areas

  • 00-system-map: system topology, interfaces, and orientation.
  • 00-constitutional-source through 18-public-observability: constitutional and operational reference domains.
  • 19-schemas-and-vocabularies: structured concepts and vocabulary work.
  • 20-conformance-and-proof: proofs, manifests, coverage, and conformance results.
  • 21-registers-and-status: bounded status registers and obligation records.
  • 22-freeze-and-releases: release, freeze, reconstruction, and non-operational boundaries.

Interpretive discipline

Do not read a collected HTML snapshot as a current fact, a label proposal as an identity determination, a review packet as an admission, or a release designation as operational authority. The records make these distinctions explicit because collapsing them is the governance failure the framework is built to prevent.
